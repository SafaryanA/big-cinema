# Тесты

## Как запускать

```
npm run test        модульные, один прогон
npm run test:watch  модульные, следят за файлами
npm run test:e2e    сквозные, поднимают проект сами
npm run verify      типы, линтер, модульные тесты, сборка
```

---

# Два вида и почему оба нужны

## Модульные — `tests/`, Vitest

### Быстрые: весь набор отрабатывает за полсекунды. Проверяют чистую логику, куда не нужен ни браузер, ни сервер.

```
helpers.test.ts       адреса, ссылки YouTube, счёт дней, разделы каталога
authSchemas.test.ts   все четыре схемы проверки форм
catalog.test.ts       отбор, порции, похожие, поиск, проекции
progress.test.ts      отметка «где остановился» с поддельным localStorage
```

## Сквозные — `e2e/`, Playwright

### Медленные: около минуты вместе со сборкой. Проверяют то, что ломалось на деле, — и ломалось именно на стыках, где модульный тест ничего не заметит.

```
video-access.spec.ts      кому какое видео достаётся, селекторы серий
search-and-locale.spec.ts страница поиска, возврат, смена языка
forms-and-theme.spec.ts   формы, тема, маршруты, карта сайта
```

---

# Три решения, которые стоит знать

## Браузер не скачивается

### В `playwright.config.ts` стоит `channel: 'msedge'` — берётся тот Edge, что уже стоит в системе. Иначе Playwright тянет свою сборку браузера на 150 МБ.

### Если Edge нет, строку надо заменить на обычный `chromium` и один раз выполнить `npx playwright install chromium`.

## `next/navigation` подменён заглушкой

### `libs/catalog.ts` тянет `@/i18n/routing`, а тот — навигацию `next-intl`, которая вне Next не разрешается. В `vitest.config.mts` стоит подмена на [stubs/nextNavigation.ts](stubs/nextNavigation.ts) плюс `server.deps.inline: ['next-intl']` — без второго подмена не доходит до кода внутри `node_modules`.

## Хранилище подделывается до импорта

### `libs/progress.ts` читает `window.localStorage` при вызове, поэтому в `progress.test.ts` хранилище ставится в `globalThis`, а модуль подгружается заново через `vi.resetModules()`. Отдельная проверка есть на **закрытое** хранилище: приватное окно, переполнение, запрет данных — страница падать не должна.

# Чего эти тесты не проверяют

### **Вид страницы.** Ни один тест не смотрит на цвета, отступы и контраст. Всё это я проверял разовыми скриптами, и в репозиторий они не попали.

### **Разметку компонентов.** Нет ни `@testing-library/react`, ни `jsdom`: компоненты проверяются только целиком, через браузер.

### **Состояние «вошёл, но без подписки».** `getCurrentUser()` всегда отдаёт человека с подпиской, и ветка «нужна подписка» в сквозных тестах не исполняется.
